From broad viewing labels to preference-focused TV recommendations

Valerii Bobrov | Individual | vmbobrov@edu.hse.ru<br/>GSB final exam: SWEET.TV recommendation | 24 October 2026

Repository: <link href="https://github.com/Vaslot1/hse-recsys-exam">https://github.com/Vaslot1/hse-recsys-exam</link>

Abstract

Predicting five preferred television programmes requires distinguishing incidental viewing from repeated high-coverage watching. This study compares training-only popularity, implicit-feedback ALS and Personalized PageRank on a fixed temporal split, then diagnoses relevance-label mismatch and changes only the PPR restart profile. The selected coverage-count restart with damping 0.25 achieves validation MAP@5 of 0.367005 across 1,260 users, while the supplied Kaggle screenshot shows a highest private score of 0.34776. Preference-focused labels and restart weights support this offline strategy, but user-level failures, tie ambiguity and repeated validation selection limit generalization claims.

1. Problem, sources and alternatives

The task is a ranked Top-5 for weeks 31-42, using channel viewing intervals and programme schedules [1]. A five-minute fragment of a one-hour broadcast can pass the initial interaction rule but fails the competition-described 80% coverage rule. The contributions are an auditable interval join, a common comparison of two eligible methods plus popularity, and a controlled correction of the restart profile. Implicit ALS separates binary preference from confidence [2]; personalized PageRank permits a nonuniform restart distribution [3]. Content-based filtering was considered for cold items but not implemented; rank fusion was deferred to avoid adding untested components.

2. Data and leakage controls

The log contains 5,821,987 rows. Matching preserves exact IDs, joins equal channel IDs, unions duplicate/overlapping views, accumulates disjoint visits within each airing, and removes ambiguous schedule seconds. ID 0 is unlabelled, never a candidate or an explicit dislike. The original threshold is O ≥ min(300, 0.5L), with full airing duration L. There are 17 duplicate view rows and 168 excluded unique views: 117 duration mismatches and 52 over-24-hour sessions, with one overlap. Saved qualifying matches total 1,233,106 for training and 859,214 for validation.

Fit: 9 March-18 May 2020; validate: 18 May-27 July; predict: 27 July-19 October (all end-exclusive, source wall-clock time). Every graph, factor and popularity count uses training only. Future schedules provide availability, not future viewing. Validation has 6,384 candidates; the future pool has 6,632. Repeats are allowed because programme IDs can recur across airings; each list has five distinct nonzero IDs. The same training distinct-viewer popularity supplies fallback and list completion.

3. Methods and ranking

Popularity ranks distinct training viewers. ALS minimizes confidence-weighted squared preference error plus L2 regularization; the selected run uses binary confidence, alpha 1, regularization 10, 32 factors, 15 iterations and seed 42. Its score is a user-item dot product. PPR uses the unchanged 2,901-node programme graph with distinct-user co-view edge weights and no self-loops. The final restart is each user’s normalized count of training airings with O/L ≥ 0.8; damping is 0.25. PPR mass ranks graph-supported candidates, with popularity/numeric-ID tie breaks and fallback. These scores are ranking quantities, not interchangeable probabilities of watching.

4. Evaluation, diagnosis and model selection

For a user with target set R, AP@5 = Σ(k=1..5) [hit(k) × hits-through-k/k] / min(5, |R|); empty targets score zero. MAP is the equal-user mean. This is binary membership, not positional agreement with the target order [3]. The original broad labels counted every qualifying programme. The aligned diagnostic retains airings with at least 80% coverage and selects the five most frequent programme IDs, breaking cutoff ties by ascending numeric ID. Fragmented visits count once per airing; different airings count separately. These conventions are explicit local assumptions, not a reconstruction of undocumented hidden code.

<b>Decision.</b> Select coverage-count restart PPR 0.25 with the existing popularity fallback for an offline deployment candidate. It leads the fixed validation comparison, reuses the graph and finishes within the budget. Its quality gain is not a demonstrated retention or revenue gain. The original score gap was largely label-definition sensitivity: uniform PPR falls from 0.738275 to 0.264163 when only labels change. This explains why broad-label validation was misleading, but does not prove that labels account for every Kaggle difference.

<b>Limitations and next step.</b> Only 10.8% of first-schedule rows have nonzero IDs; this is a row fraction, not measured airtime coverage. Timestamp timezone, hidden fragmentation and tie rules remain uncertain. Cold items lack learned graph/factor support, quarantine changes usable evidence, and validation has been reused for tuning. The same two users reveal both personalization benefit and a complete failure. A next experiment would evaluate the fixed selected configuration on a new earlier rolling temporal holdout before further tuning; it has not been run.
